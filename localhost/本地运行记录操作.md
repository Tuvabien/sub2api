### 1.2 服务运行检查

> **重要**：以下命令是 **PowerShell 专有命令**，必须在 PowerShell 中执行。
> - 在 `cmd` 中执行会报 `'Get-Service' 不是内部或外部命令`
> - 在 `git bash` 中执行会报 `command not found`
> - 打开 PowerShell：`Win+R` → 输入 `powershell` → 回车

```powershell
# 检查 PostgreSQL 服务状态（PowerShell 专有命令）
Get-Service -Name "postgresql-x64-18" | Select-Object Name, Status, StartType

# 检查端口监听（PG=5432, Redis=6379）（PowerShell 专有命令）
Test-NetConnection -ComputerName 127.0.0.1 -Port 5432 -WarningAction SilentlyContinue | Select-Object TcpTestSucceeded
Test-NetConnection -ComputerName 127.0.0.1 -Port 6379 -WarningAction SilentlyContinue | Select-Object TcpTestSucceeded
```

**命令含义说明**：

| 命令 | 含义 |
|------|------|
| `Get-Service -Name "postgresql-x64-18"` | 查询 Windows 服务管理器中指定服务的状态（Running/Stopped） |
| `Test-NetConnection -ComputerName 127.0.0.1 -Port 5432` | 测试到目标 IP+端口的 TCP 连通性（相当于 telnet） |
| `Select-Object TcpTestSucceeded` | 只输出 `TcpTestSucceeded` 字段（True/False） |

**在 cmd / git bash 中的替代命令**：

```cmd
:: cmd 中检查 Windows 服务
sc query postgresql-x64-18

:: cmd 中检查端口（需启用 telnet 客户端：控制面板 → 程序 → 启用 Windows 功能 → Telnet Client）
telnet 127.0.0.1 5432

:: cmd 中查看端口监听
netstat -an | findstr "5432 6379"
```

```bash
# git bash 中调用 PowerShell 执行（最简单）
powershell.exe -Command "Get-Service postgresql-x64-18"

# git bash 中检查端口
netstat -an | grep -E "5432|6379"
```

## 二、后端启动步骤

### 2.1 进入后端目录

```powershell
cd d:\working\AI\sub2api\backend
```

### 2.2 同步 Go 工具链与依赖（首次或拉取新代码后执行）

#### 设置 GOTOOLCHAIN（三种方式，任选其一）

`go.mod` 要求 Go ≥ 1.26.5，本机只有 1.26.4，需设置 `GOTOOLCHAIN=auto` 让 Go 自动下载所需版本。

> **`$env:GOTOOLCHAIN="auto"` 的含义**：这是 PowerShell 设置环境变量的语法，`$env:` 前缀表示操作环境变量。但这种方式**只在当前 PowerShell 窗口有效**，关闭窗口后失效。

**方式一：Go 官方推荐（永久生效，推荐）**

```powershell
# 写入 Go 的环境配置文件（%USERPROFILE%\AppData\Roaming\go\env）
# 只需执行一次，所有终端永久生效
go env -w GOTOOLCHAIN=auto
```

执行后无需再手动设置 `$env:GOTOOLCHAIN`，所有新开的终端都会自动生效。

**方式二：PowerShell 会话级临时设置（关闭窗口失效）**

```powershell
# 每次新开 PowerShell 窗口都要执行
$env:GOTOOLCHAIN="auto"
```

**方式三：Windows 系统环境变量（永久生效）**

```powershell
# 通过 PowerShell 设置用户级环境变量（永久）
[Environment]::SetEnvironmentVariable("GOTOOLCHAIN", "auto", "User")

# 设置后需重新打开终端才会生效
# 或在 系统属性 → 高级 → 环境变量 中手动添加
```

#### 下载依赖

```powershell
# 如果用方式二，需先执行 $env:GOTOOLCHAIN="auto"
# 如果用方式一或三，可直接执行

# 下载/更新依赖到本地模块缓存
go mod download

# 验证编译（可选）
go build ./cmd/server/
```

> **升级包命令**（按需）：
> ```powershell
> # 添加新依赖
> go get github.com/xxx/yyy@latest
>
> # 升级所有依赖到最新 minor 版本
> go get -u ./...
>
> # 整理 go.mod / go.sum
> go mod tidy
>
> # 重新生成 ent 代码（修改 ent/schema/*.go 后必须执行）
> go generate ./ent
> go generate ./cmd/server
> ```

### 2.3 启动后端服务（端口 8080）

#### 方式一：使用 config.yaml 配置文件（推荐，已创建）

已在 `backend/config.yaml` 创建配置文件，所有配置项集中管理，**只需 2 个环境变量**即可启动：

```powershell
# 在 backend 目录下执行
# SKIP_SETUP 和 GOTOOLCHAIN 不是 config.yaml 配置项，必须用环境变量
$env:SKIP_SETUP="true"       # 跳过安装向导（数据库已初始化）
$env:GOTOOLCHAIN="auto"      # 如果已执行 go env -w GOTOOLCHAIN=auto，此行可省略

go run ./cmd/server/
```

**config.yaml 配置文件位置**：`d:\working\AI\sub2api\backend\config.yaml`

> **配置文件查找机制**（见 `internal/config/config.go` 的 `configureConfigSource()`）：
> 1. `CONFIG_FILE` 环境变量指定的路径（最高优先级）
> 2. `DATA_DIR` 环境变量目录
> 3. `/app/data`（Windows 解析为 `D:\app\data`）
> 4. `.`（当前工作目录，即 `backend/`）← **本配置文件在此位置**
> 5. `./config`
> 6. `/etc/sub2api`

> **配置优先级**（高 → 低）：
> 1. 环境变量（会覆盖 config.yaml 中的同名配置）
> 2. `config.yaml` 文件
> 3. 代码内置默认值（见 `internal/config/config.go` 的 `setDefaults()`）

#### 方式二：全部使用环境变量（不推荐，命令冗长）

如果不想用 config.yaml，可以全部通过环境变量设置：

```powershell
# 在 backend 目录下执行
$env:GOTOOLCHAIN="auto"
$env:SKIP_SETUP="true"                                          # 跳过安装向导（数据库已初始化）
$env:DATABASE_HOST="127.0.0.1"                                  # 避免 localhost 的 IPv6 坑
$env:DATABASE_USER="postgres"
$env:DATABASE_PASSWORD="123456"
$env:DATABASE_DBNAME="sub2api"
$env:DATABASE_SSLMODE="disable"
$env:REDIS_HOST="127.0.0.1"
$env:SERVER_MODE="debug"
$env:SERVER_HOST="0.0.0.0"
$env:SERVER_PORT="8080"
$env:JWT_SECRET="f48fbcd28277b27b444ff6c3967542c00276e8ef7c4e41716e"  # 会被持久化值覆盖，可任意填
$env:TOTP_ENCRYPTION_KEY="0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"  # 必须 64 位 hex
$env:LOG_OUTPUT_TO_FILE="false"                                  # 禁用文件日志（沙盒禁止写 D:\app\data\logs）
$env:LOG_OUTPUT_TO_STDOUT="true"
$env:TZ="Asia/Shanghai"

go run ./cmd/server/
```

#### 环境变量 vs 配置文件说明

> **环境变量不保存到任何文件**，它们是**进程级临时设置**，只对当前 `go run` 进程有效，关闭终端后失效。每次启动都要重新设置。
>
> **config.yaml 是持久化文件**，修改后保存即可，下次启动自动读取，无需重复输入命令。
>
> **`SKIP_SETUP` 和 `GOTOOLCHAIN` 不是 config.yaml 配置项**：
> - `SKIP_SETUP`：控制是否跳过安装向导，在 `internal/setup/setup.go` 中通过 `os.Getenv("SKIP_SETUP")` 读取，只能用环境变量
> - `GOTOOLCHAIN`：Go 工具链配置，由 Go 运行时读取，不是项目配置项，只能用环境变量或 `go env -w`
>
> **`JWT_SECRET` 会从数据库读取持久化值**：后端启动时会从 `security_secrets` 表读取 `jwt_secret`，覆盖 config.yaml 和环境变量中的值，所以 config.yaml 中的 `jwt.secret` 可填占位符。

## 三、前端启动步骤

### 3.1 进入前端目录

```powershell
cd d:\working\AI\sub2api\frontend
```

### 3.2 安装依赖（首次或拉取新代码后执行）

```powershell
# 必须使用 pnpm，禁止使用 npm/yarn（会产生 node_modules 冲突）
pnpm install --no-frozen-lockfile
```

> **为什么加 `--no-frozen-lockfile`**：
> - `package.json` 中的 `pnpm.overrides` 字段在 pnpm 11+ 已被废弃，需迁移到 `pnpm-workspace.yaml`
> - 但 `pnpm-lock.yaml` 是用旧版 pnpm 生成的，仍包含 overrides 配置
> - 直接 `pnpm install`（默认 `--frozen-lockfile`）会报 `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`
> - 解决方案二选一：
>   - **临时方案**（推荐，本次启动使用）：`pnpm install --no-frozen-lockfile`
>   - **彻底方案**：创建 `pnpm-workspace.yaml`，把 `pnpm.overrides` 迁移过去

### 3.3 处理构建脚本警告（pnpm 11 严格策略）

如果安装过程出现以下错误：

```
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild@0.21.5, vue-demi@0.14.10
Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.
```

需要批准构建脚本（在 `frontend` 目录执行）：

```powershell
# 方案 A：交互式批准（推荐）
pnpm approve-builds
# 然后选择 esbuild 和 vue-demi

# 方案 B：创建 pnpm-workspace.yaml（彻底方案）
# 内容：
# onlyBuiltDependencies:
#   - esbuild
#   - vue-demi
```

> **本次启动的实际情况**：依赖已安装到 `node_modules`，Vite 可正常启动，未执行 approve-builds 也不影响开发服务器运行。

### 3.7 前端 Vite 配置要点

`vite.config.ts` 关键配置：

- 监听端口：`3000`（可通过 `VITE_DEV_PORT` 环境变量覆盖）
- 监听地址：`0.0.0.0`（局域网可访问）

    '/api':    { target: backendUrl, changeOrigin: true },
    '/v1':     { target: backendUrl, changeOrigin: true },
    '/setup':  { target: backendUrl, changeOrigin: true }
  }
}

## 五、本次启动遇到的问题与解决方案

### 问题 1：Go 工具链版本不匹配

**现象**：
```
go: go.mod requires go >= 1.26.5 (running go 1.26.4; GOTOOLCHAIN=local)
```

**原因**：本机 Go 1.26.4，`go.mod` 要求 1.26.5，且 `GOTOOLCHAIN=local` 禁止自动下载。

**解决**：设置 `GOTOOLCHAIN=auto`，Go 会自动下载 1.26.5 到工具链缓存。

```powershell
$env:GOTOOLCHAIN="auto"
```

### 问题 2：后端启动安装向导而非主服务

**现象**：日志显示 `First run detected, starting setup wizard...`，启动的是 `/setup/*` 路由而非主 API。

**原因**：
- 后端 `GetDataDir()` 返回 `/app/data`（Windows 解析为 `D:\app\data`）
- 该目录下存在 `.installed` 锁文件，但 `os.Stat` 在 Go 进程中未正确识别
- 导致 `NeedsSetup()` 返回 true，触发安装向导

**解决**：设置 `SKIP_SETUP=true` 强制跳过安装向导。

```powershell
$env:SKIP_SETUP="true"
```

### 问题 3：TOTP 加密密钥格式错误

**现象**：
```
Failed to initialize application: invalid totp encryption key: encoding/hex: invalid byte: U+006C 'l'
```

**原因**：`TOTP_ENCRYPTION_KEY` 必须是 64 位十六进制字符（32 字节，AES-256），不能包含 `l` 等非 hex 字符。

**解决**：使用合法的 64 位 hex 字符串：

```powershell
$env:TOTP_ENCRYPTION_KEY="0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

### 问题 4：日志文件写入权限被拒绝

**现象**：
```
write error: write /app/data/logs/sub2api.log: Access is denied.
TRAE Sandbox Error: hit restricted
  Not allow operate files: D:\app\data\logs\sub2api.log
```

**原因**：Trae 沙盒禁止写入 `D:\app\data\logs\` 目录。

**解决**：禁用文件日志，仅输出到 stdout。

```powershell
$env:LOG_OUTPUT_TO_FILE="false"
$env:LOG_OUTPUT_TO_STDOUT="true"
```

### 问题 5：pnpm install 报 `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`

**现象**：
```
[ERR_PNPM_LOCKFILE_CONFIG_MISMATCH] Cannot proceed with the frozen installation.
The current "overrides" configuration doesn't match the value found in the lockfile
```

**原因**：`package.json` 中的 `pnpm.overrides` 字段在 pnpm 11+ 已废弃，需迁移到 `pnpm-workspace.yaml`。

**解决**：

```powershell
pnpm install --no-frozen-lockfile
```

### 问题 6：`pnpm dev` 因 `ERR_PNPM_IGNORED_BUILDS` 退出

**现象**：`pnpm dev` 启动前会运行 `pnpm install` 做 pre-flight check，遇到 `ERR_PNPM_IGNORED_BUILDS` 错误退出。

**原因**：pnpm 11 默认禁止 `esbuild`、`vue-demi` 的 postinstall 脚本。

**解决**（二选一）：

```powershell
# 方案 A：彻底批准（推荐）
pnpm approve-builds

# 方案 B：绕过 pre-flight check（本次启动使用）
node node_modules/vite/bin/vite.js
```

## 七、一键启动脚本（PowerShell）

将以下内容保存为 `start-dev.ps1`，可一键启动前后端：

```powershell
# start-dev.ps1 - 一键启动 sub2api 开发环境
# 用法：在项目根目录执行 .\start-dev.ps1
# 依赖：backend/config.yaml 配置文件已存在（已创建）

$ErrorActionPreference = "Stop"

# 启动后端（新窗口）
# 使用 backend/config.yaml 配置文件，仅需 2 个环境变量
$startBackend = {
    Set-Location "d:\working\AI\sub2api\backend"
    $env:SKIP_SETUP="true"       # 跳过安装向导（数据库已初始化）
    $env:GOTOOLCHAIN="auto"      # 如果已执行 go env -w GOTOOLCHAIN=auto，此行可省略
    go run ./cmd/server/
}
Start-Process powershell -ArgumentList "-NoExit", "-Command", $startBackend.ToString()

# 启动前端（新窗口）
$startFrontend = {
    Set-Location "d:\working\AI\sub2api\frontend"
    node node_modules/vite/bin/vite.js
}
Start-Process powershell -ArgumentList "-NoExit", "-Command", $startFrontend.ToString()

Write-Host "前端: http://localhost:3000"
Write-Host "后端: http://localhost:8080"
```
